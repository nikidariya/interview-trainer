# Договор между частями проекта

Все части общаются обычными вызовами функций на Python. Данные передаются структурами из `app/schemas.py`.
Менять сигнатуры функций ниже нельзя: на них опираются остальные роли. Внутри функции можно делать что угодно.

| Роль | Функция | Принимает | Возвращает |
|---|---|---|---|
| 1 | `analyst.build_plan` | текст вакансии | `InterviewPlan` (роль, уровень, список тем) |
| 1 | `interviewer.next_question` | план, история, номер темы, флаг `clarify` | текст вопроса |
| 2 | `evaluator.score_answer` | вопрос, ответ | `AnswerScore` |
| 2 | `coach.final_report` | план, история, список оценок | текст итогового разбора |
| 3 | `InterviewSession` | `start(текст вакансии)`, `submit_answer(ответ)`, `report()` | вопрос, следующий вопрос или `None`, текст разбора |
| 4 | `gigachat_client.chat` | имя агента, промпт роли, список сообщений | текст ответа модели |
| 4 | `parsing.*` | текст ответа модели | список, словарь или число |

## Правила для агентов

1. К LLM обращаться только через `gigachat_client.chat`, не напрямую.
2. Просить у модели простой формат: нумерованный список или строки «Ключ: значение». JSON не использовать.
3. Читать ответ только через функции `app/parsing.py`. Если модель ответила не по формату, брать значение по умолчанию.
4. Промпты хранить в `prompts/<имя>.md` и загружать через `app.prompts.load_prompt`.
5. Пока агент не готов, в его файле остаётся заглушка, и остальные роли работают с ней.
