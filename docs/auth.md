# Регистрация и вход

Стартовая страница сразу показывает форму вакансии. Полное интервью с итоговым
разбором доступно без аккаунта и без ограничения количества попыток. Гостевой
режим не обращается к PostgreSQL.

Кнопка «Войти» в шапке открывает окно с вкладками «Вход» и «Регистрация».
После регистрации пользователь сразу входит в приложение. Google остаётся
дополнительным способом входа, если заполнен `.streamlit/secrets.toml`.
Крестик, Escape и клик вне окна закрывают окно,
сохраняя черновик вакансии и текущее интервью. Ошибка входа также не сбрасывает ответы.

## Запуск через Docker

1. Создайте `.env` из `.env.example`, если файла ещё нет, и настройте GigaChat.
2. Задайте в `.env` случайный `POSTGRES_PASSWORD`. Можно сгенерировать его командой:

   ```powershell
   python -c "import secrets; print(secrets.token_urlsafe(36))"
   ```

3. Запустите Docker Desktop, затем:

   ```powershell
   docker compose up --build -d
   ```

4. Откройте http://localhost:8501, нажмите «Войти», выберите «Регистрация», введите логин,
   пароль и подтверждение.

Compose запускает PostgreSQL 17, ждёт его готовности и запускает приложение.
Таблицы `users` и `interviews` создаются автоматически при первом обращении к
аккаунтам. После обновления приложения перезапустите его: существующие аккаунты
сохранятся, таблица интервью и её индекс будут добавлены автоматически.
Пароль PostgreSQL — отдельный технический секрет, он не является паролем аккаунта
пользователя. Не публикуйте `.env` и `.streamlit/secrets.toml`.

База сохраняется в томе `postgres_data`: обычные перезапуски и `docker compose down`
её не удаляют. **`docker compose down -v` удаляет том, всех пользователей и историю интервью.**
При смене `POSTGRES_PASSWORD` в существующей базе пароль роли необходимо также
изменить в PostgreSQL; одно редактирование `.env` его не меняет.

## Запуск Python на компьютере

```powershell
docker compose up -d db
python -m pip install -r requirements.txt
python -m streamlit run app/ui.py
```

По умолчанию приложение подключается к `127.0.0.1:5433`, базе
`interview_trainer`, пользователю `interview`. Настройки задаются через
`POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`
в `.env`. Внутри Compose адрес базы автоматически заменяется на `db:5432`.
Порт базы опубликован только на loopback-интерфейсе компьютера.

## Поведение аккаунтов

- Логин: 3–32 символа, латинские буквы, цифры, `_`, `.`, `-`.
  Регистр не учитывается; `Alice` и `alice` — один логин.
- Пароль: 8–128 символов, без обрезания пробелов; можно использовать длинную фразу.
  В базе хранится только Argon2id-хеш с индивидуальной случайной солью.
- После 5 неверных попыток вход по этому логину блокируется на 15 минут.
  Ограничение хранится в PostgreSQL и действует между сессиями и перезапусками.
- Вход по паролю действует в текущей Streamlit-сессии максимум 12 часов.
  Полная перезагрузка страницы, новая вкладка или перезапуск сервера могут
  потребовать повторного входа. Постоянная cookie «Запомнить меня» не добавлена.
- «Новое интервью» сохраняет вход и историю, открывая чистую форму вакансии.
  «Выйти» очищает текущую сессию интерфейса, но не удаляет интервью из базы.
- После успешного входа или регистрации открывается пустая форма вакансии.
  Гостевое интервью не переносится в аккаунт; перед входом во время интервью
  показывается предупреждение. Переход в Google также может сбросить интервью.
- Выход и истечение сессии возвращают гостевую стартовую страницу без старых ответов.
  При ошибке проверки аккаунта доступны повторная проверка и выход в гостевой режим.
- Во время запроса к модели вход, выход и перезапуск интервью недоступны.
- Google-пользователи определяются по `sub` и записываются в ту же таблицу.
  Google и локальный аккаунт не объединяются автоматически по имени или email.
- Восстановление и смена пароля, подтверждение email и связывание аккаунтов
  пока не реализованы.

## История интервью

Для локальных и Google-аккаунтов история отображается в боковой панели:
название роли и уровень, время последнего изменения (МСК), статус. Недавно
изменённые интервью показываются первыми. После входа открывается форма новой
вакансии; для продолжения выберите сохранённое интервью. Пустая форма не создаёт
запись: интервью появляется после отправки валидного по длине текста вакансии.

В PostgreSQL сохраняются исходная вакансия, сообщения, план, оценки, прогресс,
итоговый разбор и ожидающее действие. Незавершённый запрос после открытия
истории запускается только кнопкой «Продолжить интервью». Уже сохранённые
вопросы и итоговый разбор повторно не генерируются. Каждый запрос к хранилищу
ограничен ID текущего аккаунта; история разных аккаунтов не объединяется.

При ошибке сохранения дальнейшие ответы и переключение интервью блокируются.
Кнопка «Повторить сохранение» записывает уже полученный результат без нового
вызова модели. До успешного сохранения не закрывайте страницу: результат
остаётся в памяти текущей сессии. Если сессия потеряна, в истории остаётся
последнее сохранённое состояние, и незавершённый запрос можно повторить.
Повтор записи после потери подтверждения от БД не создаёт дубликаты.

При одновременном изменении диалога в другой вкладке приложение предлагает
загрузить актуальную версию. Это заменяет локальные несохранённые изменения.
Удаление, переименование, поиск и экспорт интервью не реализованы.
Гостевые диалоги и диалоги, потерянные до внедрения хранения, восстановить нельзя.

При публикации приложение должно работать через HTTPS. Ограничение попыток
на аккаунт не заменяет ограничения частоты запросов на уровне прокси для
публичного сервиса (включая массовую регистрацию).

## Проверки

Обычные тесты:

```powershell
python -m pytest -q
```

Браузерная проверка стартовой страницы и модального окна (нужен Playwright
с Chromium и запущенное приложение):

```powershell
python tests/browser_guest_smoke.py http://localhost:8501
```

Для установленного Edge задайте `$env:PLAYWRIGHT_CHANNEL = "msedge"`.
Проверка не вызывает модель и не создаёт аккаунты.

Тесты с настоящим PostgreSQL (база должна быть запущена и доступна):

```powershell
$env:RUN_POSTGRES_TESTS = "1"
python -m pytest tests/test_users_postgres.py tests/test_interviews_postgres.py -q
```

Интеграционные тесты создают отдельную временную схему со случайным именем
и удаляют только её после проверки; рабочие аккаунты не изменяются.

Хеширование основано на [рекомендациях OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
и библиотеке [argon2-cffi](https://argon2-cffi.readthedocs.io/en/stable/howto.html).
