# Вход через Google

Google — дополнительный способ входа рядом с логином и паролем. Сначала настройте
PostgreSQL по [общей инструкции](auth.md). Streamlit и Authlib выполняют
OIDC-проверки и управляют cookie входа. Доступ разрешён любому аккаунту,
которому разрешён вход в настройках Google OAuth-приложения.

## Настройка Google

1. Создайте или выберите проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Откройте Google Auth Platform. В Branding заполните название приложения,
   контактный email и остальные обязательные поля.
3. В Audience выберите External для личных Google-аккаунтов. На этапе тестирования
   добавьте аккаунты разработчиков в Test users, если этого требует Google.
4. В Clients создайте OAuth-клиент типа **Web application**.
5. В Authorized redirect URIs добавьте точный адрес:
   `http://localhost:8501/oauth2callback`.
6. Сохраните Client ID и Client Secret в локальном файле, описанном ниже.
   Приложению нужны только стандартные разрешения `openid profile email`.

## Локальный запуск

Из корня репозитория в PowerShell:

```powershell
Copy-Item .streamlit/secrets.toml.example .streamlit/secrets.toml
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

В `.streamlit/secrets.toml` замените `REPLACE_...`: впишите Client ID,
Client Secret и сгенерированное значение `cookie_secret`. Cookie secret используется
только приложением, его не нужно передавать Google. Не публикуйте эти секреты.

Установите обновлённые зависимости и запустите приложение:

```powershell
pip install -r requirements.txt
python -m streamlit run app/ui.py
```

Откройте именно `http://localhost:8501`, нажмите «Войти через Google» и выберите
аккаунт. После возврата появится форма вакансии, а в шапке — аккаунт и
кнопка «Выйти». При выходе текущее интервью очищается.

Для Docker после создания и заполнения того же файла:

```powershell
docker compose up --build
```

Каталог `.streamlit` подключается в контейнер только для чтения; секреты не включаются в образ.
Если файла секретов нет, доступны гостевое интервью и вход по логину и паролю.
После изменения секретов перезапустите приложение.

## Публикация

Используйте HTTPS. Укажите `https://ВАШ-ДОМЕН/oauth2callback` и в Google Console,
и в `redirect_uri`. Настройте Branding/Audience для публичного доступа и пройдите
проверки, которые запросит Google. На сервере предоставьте собственный файл
секретов; для нескольких экземпляров приложения используйте одинаковый
`cookie_secret`. Секреты исключены из Git и контекста сборки Docker.

## Проверка

- Без входа доступно полное гостевое интервью с итоговым разбором.
- После входа можно начать интервью; обновление страницы сохраняет вход.
- «Новое интервью» открывает чистую форму, сохраняя вход и предыдущие диалоги.
- «Выйти» возвращает гостевую стартовую страницу; история остаётся в базе.
- Вход другим аккаунтом не показывает ответы предыдущего пользователя.
- Если пользователь отменяет вход в Google, он может вернуться к гостевой странице;
  сохранение интервью при переходе в Google не гарантируется.
- При `redirect_uri_mismatch` проверьте точное совпадение адреса, схемы и порта.

Реестр пользователей сохраняется в PostgreSQL, Google-аккаунт определяется по
`st.user.sub`. История интервью сохраняется в PostgreSQL и доступна после
повторного входа: незавершённые интервью можно продолжать из боковой панели.
Пароли Google приложение не получает.
Cookie входа Streamlit действует до 30 дней; выход завершает текущую сессию,
но не отзывает уже открытые сессии в других вкладках и на других устройствах.

Официальная документация: [Google OIDC в Streamlit](https://docs.streamlit.io/develop/tutorials/authentication/google).
