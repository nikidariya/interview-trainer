# Роль 1. Агенты-собеседники

Текст со скриншота, предоставленного участником команды.

Общий принцип, чтобы не путаться. У проекта четыре части, и у каждой есть **владелец**. Части общаются через функции из `docs/CONTRACT.md`, так что каждый работает у себя и не ждёт остальных: пока чужая часть не готова, вместо неё работает заглушка.

**Суть.** Это «мозг» проекта: два агента, которые разбирают вакансию и ведут сам разговор. Больше всего работы здесь с промптами, то есть с текстом инструкций для GigaChat.

**Файлы.** `app/agents/analyst.py`, `app/agents/interviewer.py`, `prompts/analyst.md`, `prompts/interviewer.md`, `requirements/agents.txt`.

## Что делает

- **Аналитик:** получает текст вакансии, возвращает план интервью: название роли, уровень и 5 тем в виде нумерованного списка.
- **Интервьюер:** получает план и историю разговора, возвращает следующий вопрос. Задаёт один вопрос за раз, не подсказывает ответ, говорит по-русски как живой человек.

**К первой защите:** оба агента работают с реальным GigaChat на разных вакансиях и не ломаются на странных текстах.

**Потом:** уточняющие вопросы (когда ответ расплывчатый), разные типы вопросов (технический и «расскажите о случае из опыта»), подстройка под уровень.

**Стыки:** результат аналитика читает роль 3, результат интервьюера показывает интерфейс. Для чтения ответов модели пользоваться `parsing.py` роли 4.

**Что рассказывать на защите:** как устроены промпты, почему такой формат ответа и как проверяли, что модель не выдумывает.
